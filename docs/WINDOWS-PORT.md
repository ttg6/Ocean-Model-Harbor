## 基线与边界

原仓库：https://github.com/xibai6668/Android-AI-gateway

基线提交：`15e42951f7ee4a661fc4b2056d8e1f1c1ef133ce`。

复用上游 `core/src`，保留供应商协议、凭证刷新策略、账号池、SSE、Gemini 转换和原测试。仅在候选路由生成处修复一个已复现的问题：显式 `provider/model` 前缀会绕过供应商停用开关。现在停用的首选供应商不会参与调用，启用的同模型备用供应商仍可用，并补充两项回归测试。Windows 项目单独加载 `core` 与 `desktop`，不加载 Android Gradle 插件或 Android SDK。

## Windows 实现

1.0.3 正式更名为「Ocean 模型港」：窗口、托盘、EXE、交付文件夹、压缩包与桌面启动入口使用新名称。数据目录与单实例锁沿用旧版 `AI Gateway Windows` 目录，以继续加载现有账号和设置。打包名称集中在 `branding.json`，打包脚本保持 ASCII 源码并显式以 UTF-8 读取中文品牌名，兼容 Windows PowerShell 5。

- 中文 Swing / FlatLaf 桌面窗口，网关、供应商与账号、模型、日志及设置五个页面。
- 所有阻塞网络操作放入后台工作线程；模型目录按供应商增量显示。
- 登录复用核心的 loopback 回调、设备授权轮询和短信接口，使用系统浏览器。
- Windows DPAPI 对所有持久化条目加密，SHA-256 键名映射规避 `custom:...` 中的 Windows 非法路径字符；原子替换文件保证凭证更新不先删除旧数据。
- 数据目录默认 `%LOCALAPPDATA%\AI Gateway Windows`，使用文件锁避免两个实例同时更新同一账号池。
- 默认只监听 `127.0.0.1`；窗口关闭后保留系统托盘，退出时关闭网关和回调监听。
- 自定义中转站配置保存时同步账号；删除账号同时移除配置中的对应 Key；停用开关同步核心供应商设置。
- 使用 `jpackage` 构建 Windows x64 EXE 和内置运行环境，整目录压缩为便携 ZIP。

## 构建兼容处理

这台 Windows 的 AF_UNIX 可以 bind 但 connect 失败。构建进程设置不存在的 `jdk.net.unixdomain.tmpdir`，使 JDK 的 PipeImpl 使用 TCP 回环后备。此设置仅限构建工具环境，构建脚本结束后恢复原环境变量。

JDK 17 的 Windows `@argfile` 启动路径使用系统代码页，Gradle 写入 UTF-8；当前项目含中文路径，测试 classpath 会被读错。测试任务把 classpath 放到 `%TEMP%` 下当前项目独占的目录，再执行测试，源码与结果仍在项目中。JDK 与 Gradle 下载包已核对官方 SHA-256。
